# CS 300: Data Structures and Algorithms
## Project Reflection

Looking back at the beginning of this course compared to where I am now, I can definitely say that I have a better understanding of what goes into creating a program. For Projects One and Two, I worked on developing a course advising system for ABC University. The purpose was to help academic advisors easily find course information, view prerequisites, and display computer science courses in alphanumeric order. While the idea sounded pretty straightforward at first, I learned that there is a lot more happening behind the scenes when it comes to organizing and accessing data.

One thing that really stood out to me throughout these projects was how important it is to choose the right data structure. In Project One, I compared vectors, hash tables, and binary search trees to see how each would handle the course information. Before working on these assignments, I probably would have focused more on whether a program worked rather than how efficiently it worked. Now I understand that the way information is stored can affect how quickly a program runs and how much memory it uses. Learning about these differences helped me make more informed decisions when designing my program.

I would be lying if I said everything went smoothly! One of my biggest challenges was troubleshooting my C++ code when something wasn't working correctly. Sometimes I would fix one issue only to discover another, which could definitely get frustrating. However, these experiences taught me to slow down, look at the problem from a different angle, and work through my code one section at a time. I also learned how valuable testing is because even small mistakes can affect the final output. Each time I worked through an issue, I became a little more comfortable figuring things out on my own.

Another lesson I am taking away from this course is that planning really does make a difference. I used to think getting started on the actual coding was the most important part, but working with pseudocode showed me why having a clear plan matters. It helped me organize the steps I needed to take and think about potential problems before they happened. I also started paying more attention to how different parts of a program connect rather than looking at everything separately.

Overall, I feel like this course helped me grow in more ways than just learning new programming concepts. I have become more mindful of writing code that someone else could understand, whether that means using descriptive names, keeping functions organized, or including comments where they are helpful. I also understand why programs should be designed so they can be updated or expanded without having to start completely over. I still have plenty to learn, but I feel much more confident approaching programming challenges than I did at the beginning of the course. These are skills I can continue building on throughout my computer science degree and eventually apply in my future career.
